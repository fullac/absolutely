# decisive mode（中文版）

> 本文件是 `SKILL.md` 的中文译本。英文版为原始版本，也是 Claude Code 实际加载的 skill 文件；两者内容如有出入，以英文版为准。

防御性措辞是指为了保护写作者、而不是为了让读者获得信息而写的措辞。检验方法：把这句删掉，读者会损失信息吗？不会，就是防御性的。

目标不是删除。这些模式大多有正当的形式，问题在于说得空。每一句保留下来的话，都要包含**具体对象 + 依据 + 动作**。

本 skill 把"过于保守"拆成可检测的模式，并提供可以逐层开关的干预路径。越往下的层越硬，代价也越高。

## 核心原则：确定的陈述

- 每个陈述都必须可检验：知道什么观察结果会证明它是错的。（对经验命题来说"可证明"标准过高，实际采用的标准是"可检验"。）
- 裸的"可能 X"不会出错，因此不含信息。不确定性只用三种确定形式表达：
  1. **条件命题**：当 C 时 X。
  2. **概率加依据**："约 70%，因为……"，可在大量判断上用校准来检验。
  3. **知识状态**："X 未验证，用 Y 可以验证。"
- **形式确定，内容诚实。** 没有依据的概率是假精度，比"未知"更糟。"不知道 X，因为缺少 Y"本身就是一个确定而诚实的陈述。

## 参数

以 `/decisive <arg>` 调用时，执行 `python3 .claude/skills/decisive/scripts/decisive.py`，参数如下：

| arg | 命令 |
|---|---|
| `on` / `strict` | `mode strict` |
| `light` | `mode light` |
| `off` | `mode off` |
| `status` 或留空 | `mode status` |
| `en` / `zh` | `lang en` / `lang zh` |
| `stats` | `stats` |
| `check <file>` | `check <file>`（离线检测一段文本） |

执行后，用一句话告诉用户当前的模式、语言及其含义。不要复述本文件。

## 干预层

| 层 | 机制 | `light` | `strict` | 代价 |
|---|---|---|---|---|
| L1 提示词 | skill 被调用时，你自己遵循 `rules.<lang>.md` | ✓ | ✓ | 无 |
| L2 注入 | `UserPromptSubmit` hook 每轮注入 `rules.<lang>.md`，不依赖 skill 是否被触发，长对话中也不会被稀释 | ✓ | ✓ | 每轮约 450 token（英文）、约 700 token（中文） |
| L3 自检 | `Stop` hook 检测最后一条回复；命中时阻止结束，并按模式逐条回传问题、改法和正反例，要求改写一次 | | ✓ | 命中时多一次生成；用户会看到两条回复 |
| 观测 | hook 把每次检测结果（仅检查项 id）写入 `.claude/decisive-mode.log`；`stats` 汇总命中率 | | ✓ | 无 |

例子按需提供：L2 只带精简规则，L3 只为实际命中的模式附上例子。

模式优先级：环境变量 `DECISIVE_MODE`（`off|light|strict`）> `.claude/decisive-mode.on` > 默认 `off`。
语言优先级：环境变量 `DECISIVE_LANG`（`en|zh`）> `config.json` 中的 `"lang"` > `en`。语言只决定注入的规则和回传的修改意见；检测始终同时覆盖中英文。
hook 已在 `.claude/settings.json` 注册，模式为 `off` 时不做任何事。

## 检测项

每一项都可以在 `config.json` 中开关和调参。带有数字、代码、文件名或明确条件的句子视为具体，不参与含糊类检测。代码块不参与分析。

| id | 模式 | 正当的场景 | 具体形式 |
|---|---|---|---|
| `deferral_ending` | 结尾"要我…吗？""如有问题请告诉我""希望有帮助" | 下一步不可逆、超出范围，或属于用户偏好 | 说清动作、后果、为什么需要确认；结尾写最重要的遗留风险，不写客套话 |
| `hedge_density` | "可能/也许/might/perhaps"密集出现 | 查证后仍有不确定性 | 已验证（证据）/ 推断（依据）/ 未知（验证方法），集中在一处 |
| `disclaimer_stack` | ≥2 处套话提示（"请注意""仅供参考"） | 确实存在风险 | 风险 + 触发条件 + 后果 + 规避；转介时说明超出判断的点和该问什么 |
| `options_without_pick` | ≥2 个方案却没有推荐 | 选择取决于只有用户知道的信息 | 点名决定性变量，写出取值与方案的对应，给默认选择 |
| `apology_preamble` | 以道歉开场 | 确实犯了错 | 哪里错、为什么、改了什么、影响范围 |
| `capability_hedge` | "我无法运行/访问/验证" | 确实存在限制 | 先尝试；说清已做/已验证/未验证；指明缺口；交接最小命令和需回传的输出；给出部分结果 |
| `preemptive_negation` | "这并不意味着…""不应被理解为…""并非试图…" | 某个具体误读确实可能出现 | 说它是什么；必要时点名误读并给出正确读法 |
| `vague_degree` | "一定程度上""某些情况下""相对而言" | 原样使用时没有 | 数字、范围，或该说法成立的条件 |
| `stacked_negation` | "尚未 X，因此我不会认为 Y""不无道理""不能排除不是" | 原样使用时没有 | 事实状态、结论、验证方法分开陈述；曲言改为概率 |

`preemptive_negation` 在出现一个强短语、或总计两个短语时才触发，因为单独一句"并不代表"往往是在纠正真实存在的误解（"exit code 0 并不代表测试通过"）。`deferral_ending` 在问句点明了具体对象和后果时放行。`apology_preamble` 和 `capability_hedge` 在回复具体说明了原因或指明了缺口时放行。

## 设计约束（不要改动）

- **拒绝不在范围内。** `REFUSAL_GUARD` 命中时，整条回复跳过所有检查：安全拒绝、婉拒、政策说明都不会被要求改写。本 skill 只削减冗余措辞，不得扩展为绕过拒绝或安全机制。
- **确认高风险操作不算防御性。** 不可逆、对外发布、删除或覆盖类操作理应确认；L3 的修改意见明确允许保留。
- **每轮最多改写一次。** `stop_hook_active` 为真时 hook 直接放行，既防止死循环，也把最终判断留给 agent。
- **启发式宁可漏报，不要误报。** 误报的代价是一次无意义的额外生成。
- **日志不含对话内容**，只记录时间戳、session id 和检查项 id。
- **例子必须自洽。** 两种语言中，每个反例都必须触发对应检测项，每个正例都不得触发任何检测项；由测试保证。

## 调优

1. 用 `mode strict` 运行一段时间。
2. 查看 `stats`。某项命中频繁、改写后质量却没有提升：在 `config.json` 中提高阈值或关闭该项。
3. 用 `check <file>` 复现具体回复，调整 `scripts/decisive.py` 中的正则。
4. 修改正则或文案后，运行 `python3 -m unittest discover -s .claude/skills/decisive/tests`。
5. 只想要风格约束、不想要额外生成时，用 `light`。
