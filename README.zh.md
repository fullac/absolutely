# absolutely

[English](README.md) | 中文

**decisive mode** 是一个 Claude Code skill，把冗余、防御性的回答改写成确定、具体的回答。英文为原始版本，中文为译本。

## 干预层

| 层 | 机制 | light | strict |
|---|---|---|---|
| L1 | 提示词规则（`rules.<lang>.md`） | ✓ | ✓ |
| L2 | `UserPromptSubmit` hook 每轮注入规则 | ✓ | ✓ |
| L3 | `Stop` hook 自检，回传问题、改法和正反例，要求改写一次 | | ✓ |
| 统计 | 日志仅记录检查项 id，由 `stats` 汇总 | | ✓ |

## 九种模式

防御性措辞是指为了保护写作者、而不是为了让读者获得信息而写的措辞。检验方法：把这句删掉，读者会损失信息吗？不会，就是防御性的。

这些模式大多有正当的形式。每个检测项针对的是空泛的写法，具体的写法会被放行。带有数字、代码、文件名或明确条件的句子视为具体。代码块不参与分析，拒绝类回复跳过所有检测。

| 类别 | 检测项 | 问题所在 |
|---|---|---|
| 推诿 | `deferral_ending`、`options_without_pick`、`capability_hedge` | 把工作或决定推回给用户 |
| 含糊 | `hedge_density`、`vague_degree` | 说法不会出错，因此不含信息 |
| 姿态 | `disclaimer_stack`、`apology_preamble` | 用态度代替内容 |
| 绕弯 | `preemptive_negation`、`stacked_negation` | 读者要把句子拆开才能找到结论 |

下面的例子就是 `Stop` hook 回传的例子；测试保证每个 ✗ 都会触发对应检测项，每个 ✓ 都不触发任何检测项。

### 推诿

**`deferral_ending`：结尾请示或客套**
- **为什么算防御性：** 把可逆、范围内的步骤推回给用户，或者用不含信息的话收尾。
- **触发条件：** 最后两行出现请示（"要我…吗""需要我…"）或客套（"如有问题请告诉我""希望对你有帮助"）。
- **放行条件：** 问句点明了具体对象和后果。
- ✗ 要我继续吗？
- ✓ 下一步是 `git push --force` 到 main，会覆盖远端 3 个提交，确认后执行。

**`options_without_pick`：列方案不推荐**
- **为什么算防御性：** 回避判断，把决策成本转给用户。
- **触发条件：** 两行或以上以"方案""选项""做法""思路"开头，且全文没有推荐。
- **放行条件：** 给出推荐、默认选择，或"不确定就选 X"。
- ✗ 方案一：Redis，优点…缺点… / 方案二：内存缓存，优点…缺点…
- ✓ 关键看是否多实例部署：单实例用内存缓存，多实例用 Redis。不确定就选 Redis，以后再迁移代价更大。

**`capability_hedge`："我无法运行/访问/验证"**
- **为什么算防御性：** 不尝试，也不说明缺什么，就宣布做不到。
- **触发条件：** 出现"我无法运行/执行/访问/验证/查看/测试/打开"等说法。
- **放行条件：** 上下文指明了具体缺口，比如缺少的环境变量、文件或命令。
- ✗ 我无法运行这段代码，你可以自己试试。
- ✓ 单元测试已通过（12/12）。集成测试需要 `DATABASE_URL`，当前环境没有。跑一下 `pytest tests/integration -x`，把第一条失败贴回来。

### 含糊

**`hedge_density`：含糊词分散各处**
- **为什么算防御性：** "可能 X"无论结果如何都成立，等于什么都没说，而且它代替了查证。
- **触发条件：** 空泛的句子里至少有 4 个含糊词（"可能""也许""似乎"），且每 100 词不少于 2.5 个。
- **放行条件：** 含糊词出现在具体的句子里时不计数。
- ✗ 可能是缓存问题，也许和配置有关，似乎是版本不兼容，或许要重装。
- ✓ 根因是缓存未失效：14:02 之后的请求全部命中旧 key（`app.log:88`）。未确认的是 CI 是否共用同一个 Redis，对比 `redis-cli info server` 输出的 `run_id` 即可确认。

**`vague_degree`：没有边界的程度词**
- **为什么算防御性：** 没有大小、没有条件的程度描述不会出错。
- **触发条件：** "一定程度上""某些情况下""相对而言""较为"等出现在没有数字或条件的句子里。
- **放行条件：** 同一句给出了数字、范围或条件。
- ✗ 一定程度上能提升性能。
- ✓ QPS 低于 1k 时 p99 延迟降低约 30%；超过 5k 后瓶颈转移到数据库，收益消失。

### 姿态

**`disclaimer_stack`：堆叠套话提示**
- **为什么算防御性：** 不指出具体风险的提示保护的是写作者，不是读者。
- **触发条件：** 空泛的句子里出现两处或以上套话（"请注意""仅供参考""建议咨询专业人士"）。
- **放行条件：** 提示里写明了触发条件、命令或数值。
- ✗ 请注意，以下内容仅供参考，风险自负。
- ✓ `rm -rf "$DIR/"` 在 `DIR` 为空时会删掉根目录，先加一行 `: "${DIR:?}"`。

**`apology_preamble`：道歉开场**
- **为什么算防御性：** 姿态性表达，不带内容。
- **触发条件：** 前 120 个字符内出现道歉。
- **放行条件：** 开头具体说明了哪里错、为什么错。
- ✗ 抱歉，之前的回答有误，给您带来困扰。
- ✓ 上一版把 UTC 当成了本地时间，导致结果偏移 8 小时。已改为 `datetime.now(timezone.utc)`，只影响 `export()`。

### 绕弯

**`preemptive_negation`：反驳没人提出的解读**
- **为什么算防御性：** 读者得先在脑子里构造出那个误解，再把它否定掉。
- **触发条件：** 出现一个强短语（"不应被理解为""并非试图""我不是说"），或两个弱短语（"并不意味着""并不代表"）。
- **放行条件：** 只出现一个弱短语，因为它往往是在纠正真实存在的误解（"exit code 0 并不代表测试通过"）。
- ✗ 这不应被理解为单元测试没有价值。
- ✓ 单元测试仍是定位逻辑错误最快的手段；它覆盖不到的是跨服务的时序问题。

**`stacked_negation`：多重否定或陈述自己的态度**
- **为什么算防御性：** 结论藏在层层否定后面；"我不会认为"说的是写作者的态度，不是事实。
- **触发条件：** "尚未 X，因此…不 Y""不无道理""不能排除不是""我不会认为"等。
- **放行条件：** 附带证据的直接判断，比如"我不认为是缓存问题：命中率是 99%"。
- ✗ 目前尚未进行压测，因此我不会认为它能承受高并发。
- ✓ 未压测，并发能力未知。跑 `wrk -c 1000 -d 30s` 即可测出。

## 用法

```sh
S=.claude/skills/decisive/scripts/decisive.py
python3 $S mode strict|light|off|status   # 或在 Claude Code 中输入 /decisive on
python3 $S lang en|zh
python3 $S check reply.txt
python3 $S stats
python3 -m unittest discover -s .claude/skills/decisive/tests
```

完整文档：[`SKILL.zh.md`](.claude/skills/decisive/SKILL.zh.md)。

## 代价和风险

- **每轮 token**：L2 每轮注入，英文约 450 token，中文约 700 token。`off` 模式无开销。
- **额外生成**：`strict` 模式下，命中的回复会触发一次改写，用户会同时看到原回复和改写后的回复。不想要这一点就用 `light`。
- **未经真实对话验证**：阈值按"宁可漏报"调过，但目前只经过单元测试验证。建议先用 `strict` 跑一段时间，用 `stats` 找出命中频繁、改写后质量却没有提升的检测项，再在 `config.json` 中调高阈值或关闭。
- **正则的局限**：检测基于正则，而不是语义判断。换个说法的冗余措辞可能漏掉，必要的句子也可能被误报；每轮最多改写一次，加上"确属必要就保留"的提示，误报的影响最多是一次改写。
- **中文 skill 文件**：Claude Code 只加载 `SKILL.md`，`SKILL.zh.md` 是对照译本。设为 `lang zh` 时，注入的规则和回传的修改意见是中文。

## 边界

拒绝不检测、不改写。高风险操作的确认不算防御性。

## 迁移到其他项目

复制 `.claude/skills/decisive/`，并把 `.claude/settings.json` 中的两个 hook 合并进目标项目的 settings。
